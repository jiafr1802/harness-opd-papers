# 复杂 Harness 蒸馏进 OPD 学生模型：卡点与可蒸馏条件

基于 LongHorizon-Harness 案例的分析 · 2026-11-08 · 证据说明见第 8 节

## 1. 摘要

**核心判断：** 一个 harness 能不能被 OPD 蒸馏进学生，取决于它给教师带来的增益属于哪一类。增益若来自“怎么做”（过程型），可以内化；若来自学生部署时拿不到的信息、权重装不下的外部状态、或另一个独立视角（信息型、状态型、独立性型），蒸馏不掉，只能保留接口，蒸馏“如何使用”。

以 LongHorizon-Harness（Manager、Executor、Auditor 三角色循环）为例，主要卡点有八个：

1. 学生的观察或动作通道比教师窄时，信息无法凭空恢复
2. 任务状态存在上下文之外，权重不是记忆
3. Auditor 的独立性是结构属性，同模型自审未必等价
4. 教师信号被切成碎片化的角色调用，与学生的长轨迹单位错位
5. 教师与学生动作空间可能不一致（CLI 对 GUI）
6. 特权条件在学生任意前缀处是否可得，on-policy 成本是否可承受
7. 教师永远在短上下文里工作，学生却要面对长上下文
8. 成本动机可能不成立：最贵的组件恰是最难蒸馏的

从中抽象出七条必要条件（第 5 节），其中最关键的两条是：**可重建性**（教师的增益所依赖的信息，学生能通过自己的输入和动作重建）和**状态可内化**（harness 不依赖学生无法自己维护的外部持久状态）。

本报告的判断大多是基于调研的分析和推断，不是实验结论，证据等级逐条标注。

## 2. 问题设定与范围

**设定。** OPD 在这里指：教师是“基座模型加 harness”，学生是“同一基座、部署时不带 harness”，学生在自己生成的轨迹上，用教师在对应状态下的分布做监督（OPHSD 的设定）。相关变体：HPD 保留部署时的 harness，只蒸馏使用方式；HAD 部署时直接把状态写给模型看。

**harness 是嵌套的。** Codex、Claude Code 本身就是内层 harness（管单次会话的工具调用与上下文）；LongHorizon-Harness 是外层，管跨多次会话的长任务。所以“去掉 harness”必须指明去掉哪一层。本报告讨论的是外层。

**分析对象：** LongHorizon-Harness（arXiv 2608.01964），一个 Manage-Execute-Audit（MEA）循环。

## 3. LongHorizon-Harness 回顾

**机制。** 每轮：Manager 从原始目标、已验证状态和失败证据，定义一个子任务（含依赖、约束、验收标准）；Executor 在全新、有预算的上下文里只做这一步；Auditor 是只读会话，独立检查环境的实际状态，看不到 Executor 的推理；Manager 据审计报告更新任务状态。Executor 的原始轨迹每轮丢弃，只有紧凑的、已验证的任务状态跨轮保留。角色隔离由外层编排和后端权限强制（Executor 可写，Manager 与 Auditor 只读），不靠模型自觉。三个角色默认可用同一个模型，也可分别配置。

**自报结果**（Qwen 3.7-Plus 骨干，Claude Code 执行后端，同模型同后端只换 harness）：

| Benchmark | 无 harness | 有 harness |
| --- | --- | --- |
| WeaveBench（114 题） | 51.8 | 80.7 |
| OSWorld 2.0 完整成功率（108 题） | 2.8 | 8.3 |
| OSWorld 2.0 部分得分 | 21.5 | 35.2 |
| Terminal-Bench 2.1 | 69.7 | 77.2（token 少 24%） |

**两个论文案例（二手转述）：**

- WEB_task_16：baseline 在一个无响应的对话框上重试 400 多步，得分 0.59；有 harness 时失败和缺失证据被记入状态，下一个 Executor 直接补证据，得分 0.92。
- DOC_task_2：baseline 直接改 XML，看到标题视觉正确就停，得分 0.00；有 harness 时 Auditor 解析 15 个标题的 XML 确认样式，得分 0.89。

**成本结构：** 据转述，Manager 约占总 token 的 2% 到 8%（两个来源数字略有出入），Auditor 占 19% 到 38%，是最大的额外开销。单步能力受限的任务（视觉感知、数学推理）收益较小。

## 4. 卡点分析

### B1. 信息通道：学生能拿到什么，取决于它的观察和动作空间

学生如果是完整的 agent，同样在环境里，同样能通过动作读取环境状态，所以“学生拿不到真值”并不成立。需要区分三种情况：

| 情况 | 性质 | 蒸馏是否有效 |
| --- | --- | --- |
| 环境里有信息，学生有读取动作，但不主动取 | 行为问题 | 有效，教“何时、如何核验” |
| 学生的观察或动作更窄（如只看截图、压缩页无展开） | 信息通道问题 | 无效，蒸馏不增加输入信息，需扩展学生通道 |
| 信息只存在于 harness 内部（账本、被丢弃的 Executor 轨迹） | 状态存储问题 | 见 B2 |

案例 2 中 baseline 本身就能读写 XML，它的失败是没有核验的行为问题，属于第一种。对 LensVLM 这类压缩输入场景，则可能落入第二种。

### B2. 状态在上下文之外

LongHorizon 的核心设计是把任务状态外置，每轮重建上下文。权重不是一份会记录本次任务进展的记忆。蒸馏能教学生“怎么读写进度记录”，但如果部署时没有这份记录，学生就必须自己维护状态（写下来或留在上下文里），这已经不是完全无 harness。HERD 的 residual memory 也属同类。

### B3. 独立性是结构属性

Auditor 另开会话、看不到 Executor 的推理、只读，因此不被执行者的思路带偏。蒸馏后，学生在自己的上下文里审自己刚做的事，导致“看起来对就当成对”的那个盲点很可能同样影响自检。**这是假设，未经实验验证。** 检验方法：同一模型，对比“独立会话审计”与“同上下文自检”在假完成案例上的检出率，差值就是独立性本身的价值，也是蒸馏的潜在上限。

### B4. 教师信号的单位错位

on-policy 蒸馏要求：学生自己生成序列，教师在同一前缀上给出逐 token 分布。但在 MEA 中：

- 教师的轨迹被切成许多短的、相互独立的角色调用，不存在一条完整长轨迹；
- 学生部署时面对的是整个任务的一条长轨迹，教师从未产生过这种分布；
- 对学生采样出的某个前缀，应以哪个角色、哪个 harness 状态作为教师条件，没有定义。

可行的绕法（建议，无文献验证）：让学生学会自己管理上下文，例如周期性写出紧凑状态再清空历史，使“分割”成为学生自己的行为。代价是需要一个写状态的接口。

### B5. 动作空间不一致

教师可以用一条 CLI 命令完成的事，GUI 学生要点多次，两者无法逐 token 对齐。GUI 动作还带坐标，同一目标有多个正确点击点，对 token 级 KL 是否合适需要核实；GUI grounding 方向的自蒸馏工作报告过：文本形式的特权信息会让蒸馏退化成 SFT，换成视觉增强的特权更有效。可选处理：限定教师只在 GUI 动作空间行动；用结果级监督；把 CLI 当作验证器或信息源，而不是动作。

### B6. 特权条件的可得性与 on-policy 成本

教师需要在学生走到的任意前缀处拿到 harness 条件。有些信息（如下一张截图）只有执行之后才有；harness 状态如果依赖整条真实轨迹，在学生的反事实前缀上无法重建。GUI 环境交互昂贵、难以重置、带随机性，on-policy rollout 的成本也需要评估。HPD 通过离线回放加状态编译绕开了这一点，代价是不再 on-policy。

### B7. 长上下文的分布差

教师的 Executor 永远在短而干净的上下文中工作，这正是它强的原因之一。学生若不带外层的分割，就要在不断变长的上下文中工作，面对教师从没处理过的分布。

### B8. 经济性可能不成立

按转述的成本结构，Manager 只占约 2% 到 8%，容易蒸馏但省得少；Auditor 占 19% 到 38%，是最大开销，却是信息型、独立性型组件，最难蒸馏。另外 Terminal-Bench 上有 harness 反而少用 24% token，说明 harness 并不必然比无 harness 贵，蒸馏省成本是待验证的假设。无 harness 的学生还可能需要更多次重试，应按“每次成功的成本”比较。

### B9. 增益来源未分解（证据缺口）

据我所见，README 和转述中没有按组件做消融（去掉 Auditor、去掉全新上下文、去掉 Manager 各掉多少）。在不知道增益来自过程型还是信息型组件之前，无法判断可蒸馏的空间。

## 5. 升维：什么样的 harness 可以被 OPD 进学生

以下七条是从卡点中抽象的**必要条件假设**，不是定理，也不是已被文献证明的结论。

| 编号 | 条件 | 含义 | 对应卡点 |
| --- | --- | --- | --- |
| C1 | 可重建性 | 教师增益所依赖的信息，必须能由学生部署时的输入加自身动作重建 | B1 |
| C2 | 状态可内化 | harness 不依赖学生无法自己维护的跨上下文外部状态；否则学生需保留写状态的接口 | B2, B7 |
| C3 | 条件可定义 | 对学生采样的任意前缀，都能构造教师的 harness 条件，且可实时计算 | B4, B6 |
| C4 | 动作空间对齐 | 教师与学生输出空间相同或可翻译，使 token 级监督有意义 | B5 |
| C5 | 增益非来自独立性 | 若增益主要来自“另一个独立视角”，同模型蒸馏会丢失 | B3 |
| C6 | 增益可归因 | 教师优势确实来自 harness 且可按组件拆分，学生能追回其中的可蒸馏部分 | B9 |
| C7 | 经济性 | 部署量大、harness 开销大，且开销集中在可蒸馏的组件上 | B8 |

**可蒸馏性光谱（由易到难，分类为本报告的归纳）：**

| 层级 | harness 类型 | 代表工作 | 增益类型 | 合适的蒸馏策略 |
| --- | --- | --- | --- | --- |
| 1 | 自包含的推理脚手架（draft–verify、plan–solve） | OPHSD | 过程型 | 可完整内化，部署时去掉 harness |
| 2 | 可由历史推断的运行时状态与控制语义 | HAD、HPD | 过程加状态推断 | 保留 harness，蒸馏使用方式；OPHSD 受控研究在多轮设定中也观察到收益有衰减 |
| 3 | 知识与技能文本 | SKILL0、Skill-SD | 知识型 | 课程式撤除或特权蒸馏，内化知识 |
| 4 | 环境真值核验 | LongHorizon 的 Auditor | 信息加独立性 | 只蒸馏“何时核验、如何判断”，学生需有等价动作 |
| 5 | 外部持久状态与记忆 | LongHorizon 账本、HERD | 状态型 | 保留接口，学生自管状态 |
| 6 | 动作捷径或不同动作空间 | CLI-Anything、ClawGUI 混合方式 | 动作型 | 结果级监督或轨迹翻译，需谨慎 |

**三种不同的“蒸馏目标”，不应混用：**

1. 内化能力（OPHSD）：部署时 harness 完全移除；
2. 内化使用方式（HPD）：部署时 harness 保留，学生学会正确与之交互；
3. 内化上下文管理（本报告建议的方向）：学生自己周期性写状态、压缩历史，把外层的“分割”变成自己的行为。

## 6. 对 LongHorizon 的建议路线

**可直接尝试：**

- Auditor 的“何时核验、如何判断成败”：前提是学生有等价的核验动作（如在 GUI 里查看样式面板，或保留文件解析工具）；
- Manager 的“拆成有界小步”：容易蒸馏，但成本占比小，价值主要在能力而不是省钱。

**需要改变设定：**

- 让学生学会自管上下文（周期写紧凑状态再清空历史），严格说是带写状态接口的“弱 harness”。

**不建议作为蒸馏目标：**

- 真实环境的独立审计（独立性）与持久账本本身，保留为外层。

**建议的第一批实验：**

1. 教师侧组件消融：去掉 Auditor、去掉全新上下文、去掉 Manager，分别看掉多少，定位增益来源；
2. 信息上界：给学生理想的 harness 状态，看性能上限；再看学生能否从自己的输入预测这些状态（类似 HPD 的 R 视图）；
3. 独立审计对同上下文自检的检出率对比；
4. 同一份权重、有无 harness 的对照；
5. 成本口径：每次成功的调用次数、token、墙钟时间。

## 7. GUI 方向的补充

我检索到的 GUI 方向蒸馏工作（GUI-SD-v2、Gated Hindsight Distillation、GUI grounding 的自蒸馏、Skill-SD、UI-Mem）都更接近特权信息自蒸馏，而非以 harness 增强的模型当教师；GUI-HARVEST 优化 harness 源码但权重冻结，不涉及蒸馏。据此，“GUI 任务加 harness 蒸馏进权重”目前看起来是空白，但这只是本轮检索的结果。一个值得考虑的组合是：先用 GUI-HARVEST 这类方法把 harness 优化出明显增益，再把它当教师蒸馏给无 harness 的学生（与 HERD 的思路同类，我未见到 GUI 上的实现）。

## 8. 证据状态与局限

- LongHorizon 部分读了仓库 README，案例和成本数据来自论文的二手转述，**未读论文全文和源码**；“外层是编排代码”是据 README 的推断。
- Manager 的 token 占比在两个转述里不一致（约 2.8% 到 8.1% 对 2.0% 到 2.8%）。
- 第 4、5 节的卡点和必要条件是分析推断，未经实验验证；B3 的独立性假设尤其需要实验。
- 光谱表中各工作的归类依据摘要和笔记，没有逐篇核对。
- GUI 蒸馏文献检索可能不完整；Self-Harness 等数字来自二手摘要。
